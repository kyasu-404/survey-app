# Макеты ONLYOFFICE для Survey-app

Один макет + N ответов → N отдельных документов в ZIP.

1. В результатах формы открыть **«Документы»**.
2. Загрузить XLSX/DOCX или создать макет (по умолчанию XLSX).
3. В редакторе выделить ячейку или поставить курсор в тексте, затем нажать вопрос
   в панели «Данные формы». Вставится `[Название вопроса]`.
4. Сохранить и вернуться к результатам кнопкой «← К результатам».
5. Нажать «Сформировать документы»: все ответы или выбранные, при желании выбрать
   вопрос для имени файла. Откроется вкладка «Результат» с уведомлением
   «Документы сформированы». Скачать отдельный файл или весь ZIP.

Формат результата соответствует макету. PDF и конвертация DOCX → XLSX не выполняются.
Макет никогда не заполняется ответами: генератор работает с отдельными копиями.
Системные поля: название формы, ID ответа, дата ответа, дата изменения ответа.

## Связи и подстановка

В DOCX используется content control с `survey-question:<integrationId>` или
`survey-system:<field>`. В XLSX тот же тег хранится в примечании к выбранной
ячейке. В диапазоне, в том числе объединённом, используется верхняя левая ячейка.
Один вопрос можно вставить в несколько мест. Связи переживают скачивание и
повторную загрузку, таблица bindings для них не нужна. Удаление примечания
XLSX снимает связь. Обычное примечание не перезаписывается без удаления пользователем.

Вопрос ищется по постоянному integrationId, значение — по имени/valueName вопроса
в конкретном response.data. Переименование заголовка не ломает макет. Удалённый
или чужой вопрос останавливает выгрузку с понятной ошибкой. Пустой ответ даёт
пустое значение; 0 сохраняется числом. Выборы отображаются подписями, несколько
значений — через `;`, файлы — именами, подписи — пометкой. Сложные объекты
представляются текстом; повторяющиеся вложенные вопросы пока недоступны.
Берутся сохранённые ответы, без фильтрации по текущей логике видимости формы.

XLSX сохраняет стили, листы, размеры, объединения и формулы. Числовой вопрос
записывается числом, текст — строкой, даже если начинается с `=`. Формулы
пересчитываются при открытии. DOCX сохраняет оформление первого текстового
фрагмента поля и окружающий документ, включая таблицы и колонтитулы.
В готовых файлах служебные связи снимаются. Старые сводные элементы
`survey-binding:` не превращаются в ответы автоматически: их нужно заменить
вопросами через новую панель. Историческая таблица bindings сохранена для данных
старой версии, её API и вычисления больше не используются.

## Сервер

Отдельный Node.js 22 сервис. Редактор ONLYOFFICE используется только для разметки,
worker thread на сервере заполняет OOXML без Document Builder и внешних сервисов.
Результаты сохраняются в приватном Storage и доступны авторизованным сотрудникам
во вкладке «Результат», включая повторное открытие окна. Показываются последние
100 выгрузок; удалить выгрузку может её создатель или администратор. Источник, ответы и генерация ограничены формой. Плагин получает токен
на 15 минут только для своей формы/документа и не может запускать выгрузки.

Одна выгрузка за раз, 1–500 ответов, до 1000 полей, до 90 МБ готовых файлов,
75 секунд расчёта; при превышении предлагается уменьшить выборку, без усечения.
Номер и полный ID ответа делают имена файлов уникальными. Обработка выполняется
в отдельном потоке с ограничением памяти. JWT проверяется, секрет шифруется
AES-256-GCM. Сохраняются приватный Storage, атомарная смена пути файла, проверка
адресов callback, подписи и версий совместного редактирования из базовой интеграции.

## Установка и обновление

На существующей БД применить миграции по порядку:

- `database/migrations/202609142100_onlyoffice.sql` (базовая интеграция);
- `database/migrations/202609152100_office_templates.sql` (макеты XLSX/DOCX);
- `database/migrations/202609152200_office_results.sql` (сохранённые результаты).

На новой БД использовать `database/supabase_schema.sql` вместо миграций.
Поместить сервис в `/opt/survey-app/office-service`, скопировать
`docker-compose.office.yml` в каталог compose Supabase. В backend `.env`:

- существующие `POSTGRES_PASSWORD`, `SERVICE_ROLE_KEY`, `PUBLIC_APP_URL`;
- постоянный `ONLYOFFICE_SETTINGS_ENCRYPTION_KEY` (`openssl rand -base64 32`);
- для Envoy `OFFICE_SUPABASE_URL=http://api-gw:8000`;
- `OFFICE_BIND_ADDRESS` — внутренний адрес сервера, если прокси на другой машине.

Ключ шифрования сохранять вместе с резервными копиями БД. Запуск:

```sh
docker compose -f docker-compose.yml -f docker-compose.mail-worker.yml -f docker-compose.office.yml up -d --build --no-deps office
```

Проксировать `/api/office/` на 8095 с сохранением пути, без access log временных
ссылок. Пример в корневом `nginx.conf`. У этих routes собственные CSP;
основной frontend разрешает `frame-src 'self'`. Установить frontend и настроить
адрес/JWT в «Настройки → ONLYOFFICE». Глобальный плагин и изменения Nextcloud
не требуются. При отключении коннектора кнопка «Документы» скрывается; ранее
сохранённые макеты и результаты остаются в хранилище. Настройки разделены на
вкладки «Оформление», «ONLYOFFICE», «SMTP», «Очистка файлов».

Объекты удаляются через очередь спустя два часа после удаления/замены документа,
чтобы не обрывать временные ссылки. Для результатов действует та же очередь.
Удаление формы каскадно удаляет её макеты и результаты.

## Проверки

`npm ci && npm test && npm audit --omit=dev --audit-level=high`

Тесты проверяют N отдельных файлов, независимость макета, повторные поля,
форматирование, формулы, числовые значения и защиту от формул в тексте,
переименование/удаление источников, приватный доступ и JWT callback.

Официальные API: [content controls](https://api.onlyoffice.com/docs/plugins/interacting-with-editors/text-document-api/Methods/AddContentControl/),
[комментарии ячеек](https://api.onlyoffice.com/docs/office-api/usage-api/spreadsheet-api/ApiRange/Methods/AddComment/),
[сохранение](https://api.onlyoffice.com/docs/docs-api/usage-api/callback-handler/).
`public/plugin/plugins.js` — библиотека установленного ONLYOFFICE 9.4.0-129,
авторские уведомления и лицензия сохранены.
