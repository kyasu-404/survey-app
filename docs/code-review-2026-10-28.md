# Проверка замечаний code review от 28 октября 2026

Подтверждённые ошибки исправлены в исходниках, baseline БД и отдельной миграции
`202610281200_code_review_fixes.sql`. Развёртывание приложений и применение миграции
к рабочей БД в эту проверку не входят.

| Замечание | Результат проверки и правка |
| --- | --- |
| Дедлайн, фильтры и статус формы | Подтверждено. Фильтры списка и SQL учитывают `is_public` вместе с дедлайном. Сортировка статуса больше не открывает вручную закрытую форму с будущим сроком. Чтение формы также не меняет её статус на активный из-за будущего дедлайна. Сырой `is_public` при истечении срока не переписывается. Зафиксированное время сортировки курсора не сохраняет истёкшую форму в фильтре активных. |
| Ожидание OnlyOffice forcesave | Подтверждено для старой ошибки. Добавлено время ошибки: ожидание продолжается при прежней ошибке и прекращается при новой, даже с тем же текстом. Ошибка не сбрасывается до успешного callback. `error: 4` уже возвращал успешный результат без ожидания; этот случай закреплён тестом. Текущий цикл ожидания составляет 30 секунд, а не указанные в замечании 15. |
| Выбор ответов сотрудником чужой формы | Подтверждено. Чекбоксы доступны всем читателям ответов, выбор передаётся в XLSX, ZIP и документы. Удаление по-прежнему требует прав автора или администратора. |
| Просмотр «Учёта сдавших» | Подтверждено. Все активные сотрудники могут открыть вкладку при наличии данных организаций. Отправка напоминаний и журнал доставки доступны автору. |
| Права администратора на рассылки и персональные ссылки | Ограничение автором намеренно закреплено кодом и SQL-тестами. По решению пользователя оно сохранено; README и документация персональных ссылок исправлены. Отключение автора не передаёт эти права администратору; механизм передачи владения не добавлялся. |
| Разные browser ID при работе с файлами | Подтверждено. ID рендерера явно передаётся при резервировании, восстановлении и удалении файла; при недоступном localStorage используется стабильный ID в памяти страницы. Конкретное утверждение об отказе `submit_form_response` с ошибкой структуры не подтверждается текущей реализацией: валидатор структуры не сравнивает ID браузера с резервацией. Нарушение восстановления/удаления и разделения квот при разных ID реально. |
| Кнопка редактирования сразу после отправки | Подтверждено. Кнопка доступна после первой отправки и каждого сохранения изменений, если сервер разрешил редактирование и настройка формы включена. Страница благодарности сохраняется. |
| Удаление новых файлов при редактировании ответа | Подтверждено. Файлы, отсутствующие в сохранённом ответе, удаляются сразу. Вложения сохранённого ответа удерживаются до успешного сохранения изменений; это также сохраняет возможность повторить неудачное редактирование. |
| Повторная выдача заданий очистки | Подтверждено. Добавлен `cleanup_claimed_at`: задание удерживается 10 минут. После неудачного удаления или остановки worker оно снова доступно; старые claims без времени можно повторить сразу. Проверки `attached`, ссылок ответа и `SKIP LOCKED` сохранены. |
| Старые фоны существующей формы | Это изображения пользовательской галереи, доступные для повторного выбора. По решению пользователя её поведение сохранено: штатная очистка не удаляет галерею существующей формы. |
| Legacy redirect теряет параметры | Подтверждено. Существующий маршрут `/survey/:id` → `/form/:id` переносит и query string, и hash, включая персональные токены. |
| Устаревшее право редактирования последнего ответа | Подтверждено. После INSERT функция перечитывает форму с учётом триггеров лимита. Общая и персональная отправка возвращают `response_editable = false`, если этим ответом форма закрыта. |
| Спецсимволы поиска ILIKE | Подтверждено. `%`, `_` и `\` экранируются как буквальные символы в клиентском фильтре и обоих SQL-путях поиска. Отдельно экранируются кавычки и обратные слеши синтаксиса PostgREST. |

Для выпуска сначала примените миграцию БД, затем обновите Office service и frontend.
Миграция добавляет две служебные колонки и заменяет функции; существующие ответы,
галерея и права управления рассылками не изменяются. Предыдущие миграции не редактировались.

## Проверки

- Frontend: 657 тестов в 82 файлах, включая проверку покрытия; строки покрыты на 76%, ветви — на 68,25%. TypeScript, ESLint, production build и bundle budget проходят.
- Office service: 41 тест проходит, один существующий тест очереди пропущен без `OFFICE_TEST_DATABASE_URL`. Новые HTTP-тесты проверяют ожидание после старой ошибки, новую ошибку с тем же текстом, отсутствие изменений и удаление документа во время ожидания.
- Проверки baseline, миграций и границ Edge Functions: 67 тестов проходят.
- SQL: новая схема и обновление baseline предыдущего коммита через миграцию проверены в отдельных локальных БД с инфраструктурными схемами Supabase. Проходят проверки статусов, буквального поиска, последнего ответа, персональных ссылок, структуры ответов, восстановления загрузок, очистки и ограниченной выгрузки более 10000 ответов. Сортировка проверена на 67 формах по всем шести колонкам в обоих направлениях.
- Отдельный настоящий PostgREST: семь проверок поиска и фильтров; восемь параллельных запросов очистки получают одну резервацию ровно один раз. Повторный запрос после завершения транзакций не получает удерживаемое задание.
- Chromium: 12 сценариев проходят. Включены редактирование сразу после отправки и после повторного сохранения, сохранение старых вложений до commit, удаление новых вложений, персональные ссылки, списки, выгрузки и отчёт.

Браузерные сценарии используют подменённые API. Office HTTP-тесты подменяют БД,
Document Server и Storage; реальная сессия Document Server и полный цикл с удалённым
Storage не проверялись. SQL и PostgREST выполнялись на настоящем PostgreSQL в отдельных
тестовых БД, которые удалены после проверок. Рабочая БД и развёрнутые сервисы не обновлялись.
