# Публичная загрузка файлов и печатный отчёт — 11.09.2026

В вопросе «Файл» при замене файла SurveyJS сначала вызывает `onClearFiles`.
Обработчик ожидал удаления объекта из Storage и при ошибке возвращал `error`.
В установленной версии SurveyJS 2.5.35 ветка ошибки не сбрасывает
`isClearingFiles`: индикатор загрузки остаётся активным, выбор файла скрывается.
Теперь очистка значения подтверждается сразу, а удаление объекта выполняется
в фоне. Если удаление не удалось, объект остаётся для штатной очистки сирот.
При редактировании уже отправленного ответа удаление по-прежнему откладывается
до успешного сохранения изменений.

Исправлено удаление отдельного вложения: учитывается `options.fileName`.
Раньше обработчик пытался удалить все объекты из `options.value`, включая файлы,
оставшиеся в ответе. При частичной ошибке загрузки нескольких файлов callback
освобождает поле до ожидания удаления уже загруженной части.

Обработчик предпросмотра зарегистрирован на всё время жизни модели, до загрузки
начальных данных. Очистка React-эффекта больше не отключает его при повторном
рендере. Загрузка и предпросмотр новых публичных вложений используют клиент без
сессии, не ожидая refresh token из личного кабинета. Старые пользовательские пути
продолжают обрабатываться авторизованным клиентом. Для передачи файлов задано
60 секунд вместо общего таймаута API 12 секунд; при скачивании таймаут действует
до получения всего тела ответа. Лимит файла остаётся 10 МБ.

Отдельно воспроизведена гонка начальной отрисовки панели действий SurveyJS:
список действий обновляется асинхронно, иногда между React render и подпиской
компонента. Модель разрешает выбор файла, но в DOM остаётся пустой
`sd-action-bar--empty`, как на скриншоте. Для файловых вопросов список действий
подготавливается до React-отрисовки через штатный `actionsContainer.flushUpdates()`.
Обработчик создания вопросов покрывает и вопросы, добавленные динамически.
До исправления три из шести повторных браузерных сценариев воспроизводили сбой;
после исправления все шесть прошли.

На stss проверены последние пять запусков `storage_cleanup_runs`:
все завершились успешно, `retention_hours = 168`, `removed_files = 0`.
Плановая очистка и ручная очистка сохраняют семидневный период ожидания.
Политики Storage, Nginx, БД и backend не изменяются. Локальные черновики по-прежнему
не сохраняют файловые вложения; после обновления страницы их нужно выбрать заново.

Падение GitHub Actions `test` в запуске
[34533914470](https://github.com/kyasu-404/survey-app/actions/runs/34533914470)
относилось к `response-print.e2e.spec.ts`: ширина даты 99.25 px вместо ожидаемых
менее 90 px. У `<col>` оставался экранный `min-width: 12ch`, зависящий от шрифта.
В печатных блоках минимум сброшен в 0 при сохранении ширины 23 mm. Проверка
усилена увеличенным шрифтом таблицы: до исправления получалось 132 px, после
исправления исходное ограничение ширины проходит. Изменение ограничено печатным
режимом HTML-отчёта внутри приложения и в скачанном документе.

Регрессионные проверки покрывают повторный рендер предпросмотра, сбой удаления
при замене, удаление одного вложения, частичную ошибку загрузки, зависшую сессию,
медленную передачу и зависшее тело HTTP-ответа. Браузерные сценарии используют
mock API и не создают ответов или файлов в рабочей БД.

Контракт SurveyJS проверен по исходникам установленной версии и
[официальной документации](https://surveyjs.io/form-library/examples/store-file-names-in-survey-results/documentation).

Итоговая проверка: 503 frontend-теста с coverage gate, TypeScript, ESLint,
83 проверки политик/миграций/tooling, 14 тестов mail-worker, 13 браузерных
сценариев (один credentialed smoke штатно пропущен). Production build и bundle
budget прошли. Аудит с теми же lockfile выполнен на stss: production gate
`--audit-level=high` проходит; найдены три moderate-зависимости, mail-worker — 0.
Обновление зависимостей в этот патч не входит.
