# Персональные ссылки организаций

В «Поделиться формой» → «Ссылка» автор или администратор включает «Персональные ссылки».
Переключатель доступен при наличии вопроса «Организация». При включении сервер создаёт
по одной постоянной случайной ссылке на каждую действующую организацию типов ОУ,
выбранных в настройках формы. XLSX содержит тип ОУ, название, номер, email и ссылку.
Повторная выгрузка и рассылка дополняют список новыми организациями, сохраняя прежние ссылки.

«Отправить организациям» после подтверждения ставит приглашения в существующую очередь
SMTP worker. В письме используются название формы, организация, персональная ссылка
и дедлайн по московскому времени, только если он задан. Окно показывает ход доставки.
Напоминания в «Учёте сдавших» отправляются только несдавшим: с персональными ссылками,
если режим включён, иначе с общей ссылкой. Тип рассылки отображается в журнале.

По персональной ссылке организация заполнена и заблокирована; сервер отклоняет замену
или удаление её значения. Ссылка предоставляет доступ к одному ответу организации:
повторная отправка не создаёт дубликат, редактирование соблюдает настройку формы.
Разные ссылки имеют отдельные черновики даже в одном браузере. Файлы сохранённого ответа
можно открыть с другого браузера по той же ссылке, без доступа к чужим вложениям.
Сам токен хранится во фрагменте URL (`#personal=…`), который не отправляется в HTTP access log
или Referer. Поэтому ссылки следует передавать соответствующим организациям.

Отключение режима приостанавливает действие ссылок; повторное включение восстанавливает
те же адреса. Общая ссылка продолжает работать. Архивные ОУ, организации неподходящих типов,
закрытые формы и истёкшие сроки делают соответствующие персональные ссылки недоступными.
Переключение режима блокируется на время активной рассылки по форме.

## Развёртывание и проверки

1. Сохранить БД, исходники, развёрнутые `mail-admin`/`form-admin` и frontend.
2. На отдельной копии production применить `202609291800_personal_form_links.sql` и
   `database/personal_links.test.sql` (имя тестовой БД должно начинаться с `survey_personal_check_`).
3. Применить миграцию, обновить обе Edge Functions, затем опубликовать frontend атомарно.
   SMTP worker использует прежний формат заданий; его обновление не требуется.
4. Проверить TypeScript, ESLint, unit/SQL/browser-тесты, production bundle budget,
   доступность новых RPC, assets и состояние сервисов. Браузерные тесты перехватывают API;
   SQL-тесты откатывают данные в отдельной базе. Реальные письма при проверках не отправляются.

Миграция аддитивна. При откате frontend и Edge Functions сохранить новую колонку и таблицу
со ссылками; не удалять токены и ответы. Откат к прежнему `mail-admin` вернёт общие ссылки
в напоминаниях, поэтому его следует согласовывать с состоянием включённых персональных ссылок.


## Редактор рассылки

Окно «Поделиться формой» имеет отдельную вкладку «Рассылка». На вкладке «Ссылка»
остаются переключатель персональных ссылок и выгрузка XLSX. Размер окна на компьютере
— до 1040 × 820 px; на телефоне окно ограничено экраном, таблица доставки прокручивается
внутри своего блока.

Рассылка состоит из трёх шагов:
1. Выбор действующих организаций из справочника: поиск по названию/email, фильтр по
   типу ОУ, выбор найденных и снятие выбора. Организации с некорректным email недоступны.
2. Редактирование темы и обычного текста. Кнопки вставляют `{Организация}`,
   `{Название формы}`, `{Дедлайн}`, `{Ссылка}` в позицию курсора. Строка с дедлайном
   удаляется при отсутствии срока; её нужно размещать отдельно от других подстановок.
   Ссылка обязательна. Можно вернуть стандартный текст. Черновик сохраняется при
   переходе между шагами и вкладками, пока окно открыто.
3. Серверный предпросмотр письма для любого выбранного получателя и отправка с
   указанием количества писем. Шаблон и адреса повторно проверяются перед постановкой
   в SMTP-очередь. Новые организации не добавляются в подтверждённый выбор автоматически.
   При изменении доступности получателей или режима ссылок нужно обновить список.

В «Учёте сдавших» тот же редактор открывается только для несдавших организаций.
Режим ссылки определяется сервером. «История отправок» показывает статусы отдельно
от подготовки письма. Рассылки, созданные прежней версией клиента, продолжают работать.

Серверные действия `prepare-mail` и `preview-mail` доступны только автору формы.
Они не создают почтовую очередь. Подготовка синхронизирует персональные ссылки через
существующий `prepare_form_mail_recipients`; новой миграции БД не требуется.
В `queue-invitations` / `queue-reminders` передаются `organizationIds`, `template`
(`subject`, `bodyText`) и ожидаемый режим `personal`. Email и URL берутся только на сервере.
