# Настройки iframe и favicon

«Настройки» доступны администратору. Вкладка `iframe` расположена после SMTP.
Сайты добавляются и удаляются в черновике; кнопка «Сохранить сайты» применяет список.
Пустой список запрещает встраивание. Каждый поддомен указывается отдельно. URL
нормализуются до origin; принимаются HTTP(S), без пути, логина, query, fragment и `*`.
Максимум 50 сайтов. Первоначально список пуст. Прямые ссылки на формы продолжают работать.

Политика применяется HTTP-заголовком CSP `frame-ancestors` на публичных `/form/:id`,
включая URL с завершающим `/`. Nginx перед выдачей HTML делает внутренний `auth_request`
к `get_form_embedding_policy` и читает `X-Form-Frame-Ancestors`. RPC всегда возвращает
конфигурацию из БД, независимо от Origin/Referer посетителя. Если БД недоступна, nginx
не выдаёт публичную страницу без ограничений. Панель управления по-прежнему запрещает
встраивание. Изменения списка действуют при следующем открытии/обновлении формы.

Механизм описан в [документации nginx](https://nginx.org/en/docs/http/ngx_http_auth_request_module.html)
и [CSP frame-ancestors](https://www.w3.org/TR/CSP3/#directive-frame-ancestors).

В «Оформлении» favicon настраивается отдельно от логотипа. Допустимы PNG, SVG и ICO до
1 МБ: квадрат 16–512 px, ICO 16–256 px. Рекомендуются 32×32 или 48×48 px. Сервер проверяет
PNG-сигнатуру и CRC/структуру, кадры ICO, дерево SVG. SVG ограничен статической графикой,
без скриптов, CSS, XML-сущностей, анимации и внешних ссылок. Внутренние ссылки на градиенты
и маски поддерживаются. Имя/Content-Type генерируются сервером по проверенному формату.

`app-settings` проверяет действующую учётную запись администратора, ограничивает реальный
размер потока запроса и сохраняет файл с уникальным именем в публичный bucket `app-favicons`.
Прямой upload от браузерного клиента в этот bucket не разрешён. После переключения пути
старый файл удаляется; при ошибке записи метаданных удаляется новый. Возврат стандартного
favicon очищает путь. Кэш ссылок не мешает обновлению: каждый новый файл имеет новый URL.
Иконка обновляется сразу у сохраняющего пользователя; открытые страницы проверяют её раз
в минуту и при возвращении фокуса. Публичные формы и страница входа получают только путь,
MIME и дату, без других параметров администрирования.

## Установка

1. Создать проверенную резервную копию БД, функций, frontend и nginx.
2. Применить `database/migrations/202609292300_site_settings_author_access.sql`.
3. Скопировать `functions/app-settings/index.ts` и `favicon.mjs` в смонтированную папку
   Edge Functions `app-settings`, обновить `mail-admin`, перезапустить Edge Functions.
4. Подготовить конфигурацию nginx на основе текущего сайта:

   ```sh
   python3 ops/render-embedding-nginx.py --config /path/current-site.conf \
     --upstream http://SUPABASE_HOST:8000 --anon-key-file /private/path/anon-key \
     --output /private/path/site.conf
   ```

   Используется публичный anon JWT, **не service_role**. Удалить временный файл ключа.
   Нужен модуль `http_auth_request`. Проверить полный конфиг через `nginx -t`, установить
   и выполнить graceful reload. В поставляемых статических шаблонах действует запрет
   встраивания, пока динамическая политика не установлена.
5. Собрать и атомарно опубликовать frontend; проверить заголовки публичных и служебных
   маршрутов, iframe в браузере, права автора и отображение favicon.

Тесты SQL выполняются только на одноразовой базе `survey_personal_check_*`:
`database/site_settings.test.sql` и `database/personal_links.test.sql`. Оба скрипта
откатывают данные, почтовый worker к этой базе не подключается.
