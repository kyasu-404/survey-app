# Сохранение макетов ONLYOFFICE: проверка 30 октября 2026

Причина сообщения «Сохранение ещё не подтверждено» подтверждена по рабочим
журналам STSS и воспроизведена локально. Document Server 9.4.0.129 присылает
`lastsave: "2026-10-30T07:34:45.000Z"`. Обработчик выполнял `Number(lastsave)`,
получал `NaN` и отвечал HTTP 400 «Некорректное время сохранения». Отклонялись
как промежуточные status=6, так и финальный status=2. Проверка стояла до загрузки
файла и записи `last_save_error`, поэтому БД могла не содержать объяснения отказа.
Запрос сохранения ожидал смену пути файла и через 30 секунд возвращал HTTP 504.

Открытый редактор и успешная проверка подключения совместимы с этим сбоем:
обратная загрузка исходного файла и callback сохранения — разные операции.
Это соответствует [контракту callback ONLYOFFICE](https://api.onlyoffice.com/docs/docs-api/usage-api/callback-handler).
Существующая проверка приложения явно оставляет callback в состоянии «Не проверено».

Рабочие исходники и локальный HEAD перед изменениями — `443e1f5`.
На STSS/MAGI выполнены диагностика, чтение БД/Storage/журналов и получение
резервных файлов. Настройки, исходники и данные рабочего приложения не менялись,
контейнеры не пересоздавались. Эти исправления ещё не развёрнуты.

| Проверка рабочего окружения | Результат |
| --- | --- |
| `survey-office`, PostgreSQL и Storage | Контейнеры healthy; Office `/health` отвечает `{"ok":true}` |
| MAGI → Office API | Публичный HTTPS health отвечает успешно; upstream STSS:8095; proxy read/send timeout 120 секунд |

| Callback | В журнале три отказа HTTP 400 для одного документа: два status=6 и один status=2; во всех `lastsave` — ISO-строка |

| Поля загруженного файла | `readTemplate` обнаруживает 0 связей; в DOCX нет content controls и служебных тегов, есть два обычных обозначения в квадратных скобках |
| Очередь генерации | Одно failed-задание с сообщением об отсутствии полей; исходный макет действительно не содержит связей |

Простое `[Название вопроса]` не заменяет content control с
`survey-question:<integrationId>` или примечание XLSX с таким тегом. Имеющийся
генератор намеренно использует постоянный ID вопроса, а не совпадение текста.
Корректный загруженный макет с тегами проходит проверку и генерацию.

Исправления в исходниках:

- ISO-значение `lastsave` преобразуется в целое число миллисекунд. Числовые значения
  и отсутствие времени остаются совместимыми; некорректные значения отклоняются.
  Сохраняются проверки подписи, версии документа и порядка force-save callbacks.
  Ошибка сохраняющего callback теперь записывается и при неверном времени.
- Ответ команды `error:4` больше не сбрасывает ошибку Storage: [эта команда сообщает
  об отсутствии новых изменений](https://api.onlyoffice.com/docs/docs-api/additional-api/command-service),
  а не об успешной записи нашим приложением. Ошибку снимает успешный callback.
- API отдельного документа возвращает `binding_count`, как API списка. Перед
  постановкой в очередь сервер проверяет наличие связанных полей.
- В редакторе добавлено явное сохранение с подтверждённым статусом. Скачивание и
  возврат сначала сохраняют документ. Неудачный запрос сохраняет открытый редактор.
  Запоздавший успешный callback снимает старую ошибку; новый ввод во время сохранения
  требует повторного сохранения. При подтверждении перечитываются метаданные и
  инвалидируется кеш списка макетов. Предупреждение о закрытии остаётся после
  передачи изменений в Document Server до подтверждения Storage.
- Пустой макет получает пояснение про панель «Данные формы» и не запускает
  заведомо неуспешную генерацию. Статус сохранения виден и на мобильном экране.

В интеграционном прогоне использовался настоящий PostgreSQL и реальные HTTP/worker
пути приложения; внешние Auth, Storage-транспорт и Document Server заменены
детерминированными тестовыми сторонами. Браузерные сценарии перехватывают API,
используют тестовый iframe редактора и не изменяют рабочие данные. Полный frontend
unit-suite и все E2E вне Office не запускались. Настоящая сессия редактирования
на production после исправления не проверялась, поскольку выпуск не выполнялся.
Миграции БД для этих изменений не требуются; выпуск затронет Office service и frontend.
