# SMTP: исключение проверки сертификата

Проверка из рабочего контейнера `survey-mail-worker` подтвердила, что
`imap.obr.gov.spb.ru:465` предъявляет самоподписанный сертификат: стандартное
подключение завершается `DEPTH_ZERO_SELF_SIGNED_CERT`; с отключённой проверкой
устанавливается TLS 1.3. Авторизация и отправка писем при этой диагностике не
выполнялись.

Администратору доступен флажок «Не проверять сертификат сервера». По умолчанию
он выключен; исключение применяется только после сохранения. При включении
показано предупреждение: шифрование сохраняется, но подлинность сервера не
проверяется. Это распространяется на TLS и STARTTLS, минимальная версия TLS
остаётся 1.2. Без шифрования флажок недоступен. Глобальные настройки TLS не меняются.

В БД добавлена колонка `mail_settings.allow_invalid_certificate boolean not null
default false`. API разрешает настройку только администратору, принимает boolean
и сохраняет прежнее значение, если старый клиент не прислал новое поле. Пароль
при пустом поле не меняется и не возвращается клиенту. Worker читает настройку
при опросе и закрывает прежний пул соединений при её смене в любую сторону.
Сообщения об ошибках сертификата больше не скрываются общим `ESOCKET`.

Проверки: 719 frontend-тестов, 35 worker-тестов, 86 проверок схемы/миграций/Edge
Functions; PostgreSQL bootstrap и обновление заполненной прежней схемы в отдельном
контейнере; lint, TypeScript, production build и bundle budget. Браузер проверил
сохранение/перезагрузку на 1440 и 390 px; вид флажка проверен в sand и graphite.
Настоящий локальный SMTP-сервер с самоподписанным сертификатом проверен для TLS и
STARTTLS: строгая проверка отклоняет подключение до авторизации, явное исключение
разрешает авторизацию, возврат строгой проверки снова отклоняет подключение.

Порядок выпуска: резервная копия и репетиция на копии production, новая миграция,
обновление runtime-копии `mail-admin`, синхронизация build-контекста и пересборка
`mail-worker`, публикация frontend с атомарной заменой `index.html` и сохранением
старых assets. Для отката вернуть прежние worker, Edge Function и frontend;
добавленную колонку можно оставить. Параметры SMTP и исключение на рабочем сервере
пользователь выбирает в интерфейсе; публикация сама не отключает проверку.
