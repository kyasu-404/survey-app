# Выгрузка вложений в ZIP — 13.09.2026

На странице ответов добавлена кнопка «Файлы в ZIP» сразу справа от «Скачать XLSX».
Обе кнопки используют `responses-export-button` и одну иконку скачивания.
Кнопка ZIP отображается только при наличии файлового вопроса в схеме формы,
включая вопросы внутри статических и динамических панелей и файловые ячейки матриц.

В архив попадают вложения из всех загруженных ответов; выделение строк относится
к удалению и не ограничивает выгрузку. Страница получает все ответы с пагинацией
API. Имена каталогов содержат номер и ID ответа, номер и название вопроса.
К имени файла добавляется порядковый номер: одинаковые названия вопросов и файлов
не приводят к перезаписи. Компоненты путей очищаются от разделителей, управляющих
символов и недопустимых символов Windows. Расширения файлов сохраняются.

Файлы Storage скачиваются авторизованным клиентом по новым подписанным ссылкам,
включая вложения публичных ответов. Ссылки из произвольных внешних источников
не запрашиваются. Старые вложения, сохранённые как Base64 Data URL, декодируются
в исходные байты. Подписи и значения других типов вопросов в ZIP не включаются.

Одновременно скачиваются максимум три файла. Во время выгрузки кнопка показывает
количество обработанных вложений и блокирует повторный запуск. Переход со страницы
отменяет скачивание. Отдельная ошибка не теряет остальные файлы: в архив добавляется
«Не удалось скачать.txt» со списком невыгруженных вложений, а уведомление содержит
число успешных и неудачных скачиваний. Если вложений нет или недоступны все,
пустой архив не создаётся; показывается соответствующее сообщение.

Для ZIP используется JSZip 3.10.1, уже присутствовавший в lockfile как зависимость
ExcelJS и теперь объявленный напрямую. Модуль экспорта загружается динамически,
архив создаётся с `STORE` без повторного сжатия документов и изображений.
Архив формируется в памяти браузера, поэтому предельный суммарный объём зависит
от доступной памяти. Политики Storage, backend, схема БД и очистка сирот не меняются.

Проверки охватывают вложенные вопросы и матрицы, одинаковые имена, целостность
байтов, Base64, отмену, ошибки скачивания и условное отображение кнопки.
Браузерный тест выгружает файлы из первого и 101-го ответа при выделении только
одной строки, открывает полученный ZIP и сравнивает все байты. Второй сценарий
проверяет частичный сбой и последующую успешную выгрузку. API в тестах подменён;
тестовые ответы и вложения в рабочей БД не создаются.

Проверено: 513 frontend-тестов с coverage gate, TypeScript, ESLint,
83 проверки политик/миграций/tooling, 14 тестов mail-worker, 15 браузерных сценариев
(один credentialed smoke штатно пропущен без тестовых учётных данных). Production build
и bundle budget проходят: 48 файлов, 6688.2 KiB; начальная загрузка JS/CSS —
716.0 KiB (190.3 KiB gzip). Аудит production-зависимостей с текущим lockfile
проходит порог CI `--audit-level=high`: high/critical отсутствуют, остаются
три ранее существовавшие moderate-зависимости.

Сборка: `files-zip-20260913`. При установке проверяются исходные SHA-256,
создаются резервные копии в `/var/backups/survey-app/files-zip-*`, затем ресурсы
устанавливаются перед атомарной заменой `dist/index.html`. Старые ресурсы остаются
доступны открытым вкладкам и для отката. Изменения в GitHub не отправляются.
