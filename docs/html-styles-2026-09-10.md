# HTML-оформление и изображения вариантов — 10.09.2026

## Причины и исправления

При прохождении формы DOMPurify удалял `style` и `<style>`, тогда как конструктор
отображал исходный HTML. Теперь конструктор, предпросмотр и прохождение используют
одинаковую обработку HTML. Исходный HTML в JSON формы сохраняется без переписывания.

CSS разбирается через `css-tree` 3.2.1. Поддерживаются разрешённые свойства оформления,
включая градиенты, тени, шрифты, отступы, трансформации и анимации. Каждый CSS-селектор
ограничивается атрибутом элементов конкретного HTML-фрагмента; ID и имена keyframes
получают собственный префикс. Дополнительные контейнеры не создаются. Глобальные стили
приложения не меняются. Повторная обработка одинакового HTML стабильна и кешируется
с ограничением размера.

Это не разрешение произвольного CSS: внешние URL, скрипты, глобальные at-rules,
псевдоэлементы, позиционирование поверх приложения и CSS-переменные отфильтровываются.
Из at-rules поддерживаются keyframes; media-запросы не поддерживаются. DOMPurify
по-прежнему ограничивает HTML. Модуль HTML/CSS загружается с формой и конструктором,
не увеличивая начальную загрузку страницы входа.

У вариантов `imagepicker` обработчик загрузки возвращал абсолютный URL Storage.
Фильтр внешних ресурсов удалял этот URL при сохранении, оставляя варианты без картинок.
Теперь ссылки на загруженные ресурсы приложения во всей схеме, включая вложенные
`choices[].imageLink`, сначала переводятся в `__APP_SURVEY_ASSET__/…`, а при открытии
разрешаются в публичные URL. Значения вариантов и ответы не изменяются. Произвольные
внешние URL по-прежнему удаляются.

В тестовой форме `7f64a1cc-b99e-40ec-abd3-a56476401862` вопрос `вопрос14` сохранил
варианты «Пункт 1» и «Пункт 2», но потерял ссылки. Оба исходных PNG присутствуют в
Storage и отвечают HTTP 200. Это не ошибка Nginx. Восстановление ссылок выполняется
после установки с резервной копией исходной схемы и проверкой revision/старых вариантов;
обновляется только массив choices этого вопроса. При конфликте редакций запись отменяется.

## Установка и откат

Релиз `html-styles-20260910T143756Z`, идентификатор сборки `html-styles-20260910`.
Исходники: `stss:/opt/survey-app`; frontend: `magi:/var/www/forms.imc-mosk.ru/dist`.
Резервные копии на соответствующих серверах:
`/var/backups/survey-app/html-styles-20260910T143756Z`.

Исходники сверяются с исходной контрольной суммой перед применением патча.
На stss зависимости frontend обновляются через `npm ci`. Ресурсы устанавливаются
перед атомарной заменой `index.html`; предыдущие ресурсы сохраняются. Nginx и backend
не меняются. Для отката frontend на magi:

```bash
sudo install -o www-data -g www-data -m 644 \
  /var/backups/survey-app/html-styles-20260910T143756Z/index-before.html \
  /var/www/forms.imc-mosk.ru/dist/index.rollback.html
sudo mv -f /var/www/forms.imc-mosk.ru/dist/index.rollback.html \
  /var/www/forms.imc-mosk.ru/dist/index.html
```

Исходники до изменения сохранены в `source-before.tar.gz`, точный патч — `change.patch`.
Перед откатом исходников необходимо проверить отсутствие последующих правок; новые
файлы перечислены в патче. После отката package-файлов снова выполнить `npm ci`.
Резервная копия схемы перед восстановлением изображений — `image-choices-before.json`
на stss. Не следует заменять ею всю форму, если после восстановления были новые правки.

Документация используемого CSS-парсера: https://github.com/csstree/csstree.
