# Подписи в ответах и печать широких HTML-отчётов — 11.09.2026

## Подписи

В метаданных колонки сохраняется тип вопроса. Значения `signaturepad` отображаются
миниатюрами в таблице ответов и тегами `img` в экранной и печатной версиях HTML.
Строки других типов не превращаются в изображения по одному лишь сходству с Data URL.
Подпись не используется как текстовое название строки при открытии ответа.

Поддерживаются PNG, JPEG и SVG — форматы SignaturePad. Принимаются только встроенные
Data URL с ограничением размера и размеров изображения. SVG проходит проверку
геометрии и атрибутов; скрипты, CSS, ссылки и внешние ресурсы не разрешаются.
Пустая подпись остаётся пустой; некорректное значение показывает короткое сообщение
вместо Base64. Исходные данные ответа и схема БД не меняются.

В XLSX изображения включаются в файл и привязываются к соответствующим ячейкам.
Сохраняются пропорции, увеличиваются ширина колонки и высота строки, учитываются
дополнительные строки заголовков страниц и разделов. Это изображения Excel Drawing,
а не формулы IMAGE или внешние ссылки. SVG преобразуется в PNG локально в браузере.
Идентичные картинки переиспользуются внутри книги. Защита текстовых значений от
формул, границы ячеек и отсутствие объединений в XLSX сохранены.

## HTML и печать

Один HTML содержит две компоновки, выбираемые CSS media:

- На экране — полная таблица, минимум 180 px на обычную колонку и горизонтальная
  прокрутка внутри отчёта. Ограничена минимальная ширина элемента grid, чтобы таблица
  не растягивала всю страницу.
- При печати — A4 landscape, поля 10 mm, текст таблицы 9 pt. До восьми вопросов
  помещаются в одну таблицу. Более широкая форма делится по страницам; широкая
  страница — по sectiontitle; оставшиеся широкие группы — по восемь колонок.
  Дата ответа добавляется в каждый блок, порядок строк и вопросов сохраняется.
- Названия страниц выделены цветом, разделов — жирным. Они находятся в строках
  заголовков, не занимая отдельные пустые колонки для непустых групп. Пустые группы
  сохраняют подписи. У страниц без названия при необходимости используется
  «Страница N». Группы различаются по ключам, а не по заголовкам.
- Заголовки таблицы, дата ответа и группирующие строки повторяются на следующих
  листах при вертикальном переносе. Новый блок начинается с нового листа.
  Столбец даты имеет ширину 23 mm, заданную также через colgroup для таблиц
  с многострочными заголовками. Длинный текст переносится, не обрезается.

Одинаковые правила компоновки применяются в приложении и скачанном HTML.
Именованный `@page responses-report` ограничивает альбомный формат этим отчётом;
стили содержимого других страниц и форм не меняются.

## Проверки

- 496 unit/component-тестов в 64 файлах; coverage gate пройден.
- TypeScript, ESLint и 83 проверки политик/миграций пройдены.
- Полный Playwright: 11 прошли, 1 существующий сценарий с отдельными учётными
  данными пропущен. После уточнения печатных стилей контейнера дополнительно
  пройден сценарий печати со скрытой боковой панелью и генерацией PDF из приложения.
- Сборка и bundle budget пройдены: 44 файла, 6584,2 KiB суммарно;
  начальные JS/CSS — 715,1 KiB, 189,3 KiB gzip.
- Production audit с порогом high пройден; сохраняются 3 прежних moderate-предупреждения.
- Проверки выполнены локально; изменения не отправляются в GitHub.

Модульные проверки охватывают форматы и недопустимые изображения, повторное чтение
XLSX с изображениями и смещениями ячеек, сохранение значений, границу восьми колонок,
одноимённые разделы, страницы без заголовков, пустые группы и архивные ключи ответов.
Браузерные проверки используют mock API и не отправляют ответы в рабочую БД.

Браузерный сценарий подписей проверяет реальные размеры PNG/JPEG/SVG, миниатюры,
XLSX после повторного чтения и картинки в скачанном HTML при печати. Сценарий широкой
формы проверяет 35 ответов и семь блоков, отсутствие горизонтального переполнения
страницы, повтор даты, полный набор значений и MediaBox реально сформированного PDF.
PDF дополнительно проверяется по тексту и визуально. Существующие тесты полного
списка ответов теперь явно проверяют экранную таблицу; печатная версия проверяется
отдельно. Таймауты и обязательные проверки не ослабляются.

## Установка

Релиз `signatures-print-20260910T211916Z`, идентификатор сборки
`signatures-print-20260911`. Исходники — `stss:/opt/survey-app`, frontend —
`magi:/var/www/forms.imc-mosk.ru/dist`. БД, backend и Nginx не меняются.

Резервные копии на обоих серверах:
`/var/backups/survey-app/signatures-print-20260910T211916Z`.
Перед применением патча исходники сверяются с состоянием предыдущего релиза.
Ресурсы устанавливаются перед атомарной заменой index.html; старые ресурсы остаются.
Для отката frontend на magi:

```bash
sudo install -o www-data -g www-data -m 644 \
  /var/backups/survey-app/signatures-print-20260910T211916Z/index-before.html \
  /var/www/forms.imc-mosk.ru/dist/index.rollback.html
sudo mv -f /var/www/forms.imc-mosk.ru/dist/index.rollback.html \
  /var/www/forms.imc-mosk.ru/dist/index.html
```

Исходники до изменения — `source-before.tar.gz`, точный патч — `change.patch`.
Перед откатом исходников следует проверить последующие правки; новые файлы
перечислены в патче. Новых зависимостей в этом изменении нет.
